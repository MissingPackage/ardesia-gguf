# Lens: industry precedents (agent report, 2026-09-16)

# Many adapters on one base: who ships it, what they published, where the frontier is

Legend: **[P]** = verified from a primary source I fetched; **[S]** = secondary source / search snippet only; **[I]** = my inference.

## 1. Production systems

**Apple Intelligence — the reference implementation of the pitch.** Apple runs a ~3B on-device model with "a broad set of adapters, each fine-tuned for a specific feature"; adapters are "dynamically loaded, temporarily cached in memory, and swapped." Rank 16, 16-bit values, applied to attention matrices, the attention projection and the point-wise FFN; "for the ~3 billion parameter on-device model, the parameters for a rank 16 adapter typically require 10s of megabytes." **[P]** (https://machinelearning.apple.com/research/introducing-apple-foundation-models, June 2024). The 2025 tech report adds: on-device model at **2-bit quantization-aware training**, embeddings 4-bit, KV-cache 8-bit; LoRA adapters are used to recover the quality lost to compression; developers get "a Python toolkit for training **rank-32** LoRA adapters"; delivery uses Background Assets to "download just a single adapter that matches the base model's version on device." **[P]** (https://arxiv.org/html/2507.13575v1, July 2025). Apple publishes **no swap-latency number and no adapter count**. **[P: absence confirmed]** Critical operational fact: "adapters must be retrained with each new version of the base model." **[S]** (https://developer.apple.com/apple-intelligence/foundation-models-adapter, 2025).

**Google Gemini Nano / AICore.** AICore holds one base model shared by multiple apps; "app developers can create small LoRA adapters based on their own training data" and ship only the adapter; the OS manages load/evict on the NPU and updates the base via Play System Updates. **[S]** (https://android-developers.googleblog.com/2023/12/a-new-foundation-for-ai-on-android.html, Dec 2023). Google itself uses per-feature LoRA (Pixel Recorder summaries; ML Kit GenAI APIs each get an API-specific adapter). **[S]** (https://android-developers.googleblog.com/2025/05/on-device-gen-ai-apis-ml-kit-gemini-nano.html, May 2025). Note: developer-trainable LoRA on AICore has stayed gated/early-access in practice — I could not confirm general availability. **[I]**

**Microsoft Phi Silica.** `LanguageModelLowRankAdapter.CreateFromPath` + `LanguageModelOptions.LowRankAdapter`, adapter file in **safetensors**, promoted to the stable Windows App SDK API (2.1.3). Adapters must be trained in the cloud (Azure Container Apps, A100 recommended, 45–60 min per job); runtime returns `IncompatibleLowRankAdapter` when base and adapter versions mismatch. **[P]** (https://learn.microsoft.com/en-us/windows/ai/apis/phi-silica-lora, page dated 2025-08-21, updated 2026-07-15). Microsoft's own Learning Zone case reports a 75% reduction in rejection rate and 4.6x subjective-quality uplift. **[S]** (https://blogs.windows.com/windowsdeveloper/2025/07/31/phi-silica-task-specialization-using-lora-in-microsoft-learning-zone-a-technical-deep-dive/).

**Predibase LoRA Land / LoRAX — the economics paper to cite.** 310 models = 10 bases x 31 tasks; 4-bit LoRA models "outperform base models by 34 points and GPT-4 by 10 points on average"; **25 LoRA-tuned Mistral-7B served on a single A100 80GB** via LoRAX with shared base weights and dynamic adapter loading. **[P]** (https://arxiv.org/abs/2405.00732, Apr 2024). Caveat to state out loud: those 31 tasks are narrow, benchmark-shaped tasks — the "beats GPT-4" number does not transfer to open-ended assistant work. **[I]**

**NVIDIA NIM.** Dynamic multi-LoRA: adapter store + multi-tier cache, specialized kernels so one request batch flows through base + several adapters; clients select the adapter by name in the `model` field; NeMo and HF PEFT adapters both supported; "subject to GPU memory limits." **[S/P-doc]** (https://docs.nvidia.com/nim/large-language-models/latest/peft.html).

**Fireworks.** "Serve hundreds of fine-tuned LoRAs on a single base model, simultaneously, at the same inference cost as a single base model"; Cresta deployed "1000s of LoRAs" on one base; serving hundreds of LoRAs "approach[es] 90% of base model performance"; LoRA does not change per-token price. **[P]** (https://fireworks.ai/blog/multi-lora, 18 Sep 2024).

**Research systems behind all of the above.** S-LoRA: adapters in host RAM, paged into GPU on demand, "thousands of LoRA adapters on a single GPU," up to 4x vLLM-packed and 30x PEFT throughput. **[S]** (https://arxiv.org/abs/2311.03285, Nov 2023). vLLM multi-LoRA is production-grade but not free: reported up to ~50% max-throughput drop in some configurations, and TTFT inflation when HBM is split between KV cache and adapters. **[S]** (https://github.com/vllm-project/vllm/issues/10062; https://blog.squeezebits.com/37065).

**Not found:** no public, numeric Salesforce / Databricks / Samsung "N adapters per GPU" disclosure. Databricks documents multi-PEFT-adapter serving as a pattern, not as a published fleet metric. **[P: absence]**

## 2. Ecosystems and marketplaces

- Hugging Face Hub: **132,387 models carry the `lora` tag** today. **[P]** (https://huggingface.co/models?other=lora, fetched 2026-09-16).
- Civitai is the existing proof that adapter libraries work socially: **868,069 unique LoRAs trained in one month** on their platform. **[S]** (https://www.runpod.io/case-studies/civitai-runpod-case-study).
- LoraHub: compose LoRA modules for unseen tasks with a few examples, no gradients; approaches (does not beat) in-context learning on BBH. **[S]** (https://arxiv.org/abs/2307.13269, COLM 2024).
- Ostapenko et al., *Towards Modular LLMs by Building and Reusing a Library of LoRAs* — model-based clustering to build the library + **Arrow**, a zero-shot router that picks adapters per input without retraining; tested on Phi-2 and Mistral. **[S]** (https://arxiv.org/abs/2405.11157, ICML 2024).
- Adapter **generation**: Sakana **Text-to-LoRA** — a hypernetwork emitting a task LoRA from a natural-language task description in one forward pass (ICML 2025) **[S]** (https://github.com/sakanaai/text-to-lora); **Drag-and-Drop LLMs** — prompts to LoRA weights, "up to 12,000x lower overhead than full fine-tuning," NeurIPS 2025 **[S]** (https://arxiv.org/abs/2506.16406); **SHINE** (2026) — in-context hypernetwork mapping context to LoRA in a single pass, submitted 6 Feb 2026 **[P]** (https://arxiv.org/abs/2602.06358). Sakana **Transformer²** replaces LoRA with RL-trained singular-value "expert vectors" mixed at inference by a two-pass dispatch **[S]** (https://sakana.ai/transformer-squared/, Jan 2025).

## 3. MoE-of-adapters and routing

LoRAMoE (ACL 2024) is the one with the enterprise-relevant finding: fine-tuning on growing instruction data **destroys world knowledge**, and a router over LoRA experts — some pinned to knowledge, some to task — preserves it. **[S]** (https://aclanthology.org/2024.acl-long.106/). MixLoRA puts top-k-routed LoRA experts in the FFN plus independent attention adapters, motivated explicitly by LoRA "falling short in multi-task scenarios" **[S]** (https://arxiv.org/abs/2404.15159). X-LoRA mixes pre-trained adapters layer-wise and token-wise via hidden states **[S]** (https://pubs.aip.org/aip/aml/article/2/2/026119/3294581/). Direction of the evidence: **naive coexistence of many adapters interferes; the fix is a learned router, and a learned router is a training artifact you now have to maintain and re-validate.** **[I]**

## 4. Enterprise claims vs evidence

- Gartner, primary: "by 2027, organizations will implement small, task-specific AI models, with usage volume at least three times more than those of general-purpose LLMs," and recommends "a composite approach involving multiple models and workflow steps." **[S, but Gartner newsroom]** (https://www.gartner.com/en/newsroom/press-releases/2025-04-09-gartner-predicts-by-2027-..., 9 Apr 2025).
- NVIDIA, *Small Language Models are the Future of Agentic AI*: SLMs are "sufficiently powerful, inherently more suitable, and necessarily more economical" for the repetitive specialized calls that dominate agentic systems. **[S]** (https://arxiv.org/abs/2506.02153, Jun 2025, rev. Sep 2025).
- The quality question is **not** settled in your favour by default. Biderman et al., *LoRA Learns Less and Forgets Less* (TMLR 2024): in standard low-rank settings LoRA **substantially underperforms** full fine-tuning on code and math, because full FT learns perturbations 10–100x higher rank **[S]** (https://arxiv.org/abs/2405.09673). *An Illusion of Equivalence* (2410.21228): LoRA introduces "intruder dimensions," making models worse at the pre-training distribution and **less robust when adapting to multiple tasks sequentially** **[S]**. Counterweight, and the one to quote: Thinking Machines, *LoRA Without Regret* — LoRA **matches** full fine-tuning when (a) applied to **all layers, especially MLP/MoE**, not attention-only, and (b) not capacity-constrained; optimal LR is consistently **10x** full-FT's **[P]** (https://thinkingmachines.ai/blog/lora/, 29 Sep 2025).
- **Honest gap:** I found **no rigorous published comparison of "fleet of adapters vs RAG vs one big fine-tune" on real enterprise workloads** with cost, accuracy and maintenance in the same table. What circulates is vendor content and blog benchmarks. **[P: absence]** That gap is an opportunity for you, not a hole in the pitch — as long as you say it's a gap.

## 5. Verdict and positioning

**Is it new? No — the architecture is commodity, and that is the good news.** One shared base + swappable LoRA adapters is exactly what Apple ships on every iPhone, what Android ships via AICore, what Windows exposes as a stable API, and what Fireworks/NIM/vLLM sell as multi-tenant serving. Presenting it as "our revolution" is the fastest way to get destroyed by anyone who read Apple's 2025 report.

**Three sentences that are true and defensible:**
1. "The pattern is proven at the largest scale that exists — Apple, Google and Microsoft all ship one base model with hot-swapped LoRA adapters on-device; we are not betting on a research idea, we are adopting a platform pattern." (Apple 2024/2025, MS Learn 2025)
2. "The economics are documented: 25 specialized adapters on one A100 (Predibase), hundreds to thousands on one base at roughly single-model inference cost (Fireworks) — the alternative is one GPU per specialization."
3. "What is genuinely ours is the *combination*: quantized GGUF base so it runs on a 16GB workstation or in the browser, adapters trained and kept in-house so no data or specialization leaves the perimeter, composable per request, and tuned for Italian enterprise register — none of the three platform vendors gives an enterprise a base it controls."

**Three claims he must not make:**
1. **"Adapters are as good as full fine-tuning."** Only under conditions: all layers including MLPs, and enough capacity for the data (Thinking Machines 2025). Biderman (TMLR 2024) shows the opposite in the code/math regime.
2. **"Compose N adapters per request and they add up."** Evidence says adapters interfere; usable composition needs a trained router (LoRAMoE, MixLoRA, Arrow), and sequential multi-task adaptation degrades (intruder dimensions, 2410.21228). Promise *selection* of one adapter per request; treat *composition* as R&D.
3. **"Zero maintenance."** Every base-model upgrade invalidates every adapter — Apple says retrain them, Windows throws `IncompatibleLowRankAdapter`. A fleet of 50 adapters is a 50-item retraining and re-evaluation backlog on each base bump. Say it before the CTO does.
